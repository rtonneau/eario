## Review Notes

Parent: base e125b0d1c69e3414ac3cd88541b6c82b377b9556. No pre-existing changes outside .work/. Mode: delegate.

Against the criteria:
1. New crate `crates/eario-hub` (lib + `eario-hub` bin), workspace member; Eario dependencies `eario-core` and `eario-runtime` only. Other dependencies are all already in the tree and declared in `[workspace.dependencies]`: axum, thiserror, tokio (+`time`), tracing, tracing-subscriber, webbrowser; dev: serde, serde_json, tempfile. `Cargo.lock` gains only the `eario-hub` package. No `deny.toml` change.
2. HTTP API (`src/http.rs`, thin handlers over `Supervisor`), served through `eario_runtime::start_routes`, so Host/Origin and token checks apply: `GET /api/app` → `AppResponse::Hub(HubInfo)` (the list: state, version, log lines when failed); `POST /api/dashboards/{slug}/start|stop|open|uninstall`; `POST /api/stop-all`; quit is the server's own `POST /api/shutdown`. Actions answer `HubInfo` (refreshed list); open answers the new contract type `eario_core::HubOpen { url }` (ts-rs binding generated). No route extracts a body or a query. Slugs are validated with `is_slug` in the supervisor (400 `hub_invalid_slug`). Every operation re-reads the registry.
3. Start: refuses `starting` (409 `hub_starting`), a live run file (409 `hub_already_running`, so no second child overwrites it), an unknown protocol (`hub_unsupported_protocol`), a registry path not directly in `bin/<slug>/` (`hub_foreign_executable`, an addition: only the hub's own copy is ever started), a missing copy, a size or SHA-256 mismatch (`hub_modified_executable`); hashing in `spawn_blocking`. Spawns `<copy> --eario-child <absolute hub/run/<slug>.json>` with `EARIO_HUB_DIR` set to the hub's absolute root (the child finds its log file even when the hub was given its directory another way), `EARIO_PORT` removed, null stdin/stdout/stderr, working directory the copy's directory, Windows `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`, Unix `process_group(0)`. A background task polls every 100 ms: `running` once the run file's token answers; `failed` on early exit or after 30 s (the process is then killed), with the last `HUB_LOG_LINES` lines written to the log since this start plus one `eario-hub:` line saying why.
4. Re-attach at start (`Supervisor::reattach`, called by `eario_hub::start`): run files whose token answers are kept, others (and unparsable ones) deleted. Quitting leaves children running (dropping `std::process::Child` does not kill).
5. `hub/hub.json` (new `HubDir::hub_file_path`, `RunFile` format: pid, address, token) is written after the server starts and removed on quit only if it still holds this hub's token. A second start that finds a live hub there prints its address, opens the browser (unless `EARIO_NO_BROWSER`) and exits 0.
6. Stop: `POST /api/shutdown` with the child's token (new `hub_dir::request_shutdown`, sharing the hand-written loopback request of `probe`). A process this hub started is killed if it has not exited after 10 s (immediately if it no longer answers); a re-attached one is waited for until it removes its run file, and reported 504 `hub_stop_timeout` if it still answers. Stop during a start cancels it (kills the process). Stop-all stops every run file's slug and every process of this hub concurrently.
7. Terminal mode (`eario_hub::run`): prints "The Eario hub is running at <url>" and the Ctrl+C line, Ctrl+C shuts down the hub's server only, prints a stop line.
8. `docs/architecture/security.md` (threat rows and a "process-start exception" section, checklist) and `AGENTS.md` (repository list, crate boundaries, security expectations) describe the bounded exception.

Design choices for the parent's eye:
- Real-executable tests locate the examples beside `CARGO_BIN_EXE_eario-hub` in the target directory (so `CARGO_TARGET_DIR`, profile and target triple are honoured without reading the variable) and fail with "<path> does not exist: build the examples first with `cargo build -p data-explorer -p signal-lab`". Chosen over tests in an example package because the tests need both examples and the hub executable at once: an example package gets only its own `CARGO_BIN_EXE_*`, so it would locate the others anyway. `cargo test --workspace` builds the examples (they have integration tests), so CI finds them. Caveat: a stale example build is used as is.
- Each test owns its temporary hub directory; the in-process test hub's `Drop` runs `Supervisor::stop_all` (graceful stop, kill fallback for its own processes), and the hub-executable test kills its process on drop. No process was left after any run.
- Concurrency: start and uninstall are serialized by an async mutex (check then act on registry and processes); the in-memory state (`children`, `starting` with a per-start number, `failed`) is behind a std mutex never held across an await. Uninstall removes only `bin/<slug>/`, then re-reads and rewrites the registry, like `--eario-uninstall`. Transient hub-file errors are not fatal: a failed stale-file deletion or `hub.json` write is logged and retried at the next start; a failed registry write returns 500 naming the file so the user can retry.
- Small changes outside the listed files: `eario_core::CHILD_ARGUMENT` (the facade now uses it instead of its own constant) and `HubOpen`; in `hub_dir`, `hub_file_path`, `read_run_file_at`, `request_shutdown`, `remove_own_run_file_at`, with tests. `run_child` now removes its run file only if it still holds its own token, so a dashboard stopping late cannot delete the run file of a new process of the same slug (the hub deletes a stale file before each start).
- The hub links eario-runtime and so eario-data/Polars; the debug `eario-hub.exe` is 9.9 MB.

Changed after self-review: start numbering in `starting` (a start's watcher could otherwise act on a later start of the same slug after a stop and a new start within one poll); stale run-file deletion logged per file with its result; an unused `options()` accessor removed; the stop-timeout test first expected 504 for a re-attached child in its shutdown grace, but such a child closes its listener at once and is correctly counted as stopped, so the 504 case now uses a server that never stops.

Known limits, not fixed: two hubs started at the same instant can both find no live hub and both run (last `hub.json` writer wins); a corrupt registry makes `/api/app` answer 500, so a second start would not see the running hub; an install by `--eario-install` racing with a hub uninstall can lose one registry update (separate processes, no file lock).
